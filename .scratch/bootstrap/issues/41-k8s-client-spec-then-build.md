# 41: Spec-then-build: the k8s_client module

**Context:** Spike S1 ([14](14-spike-s1-in-cluster-client.md)) settled TLS, token reload and the verbs in [Decision 0013](../../../docs/decisions/0013-in-cluster-client.md) and left `docs/specs/k8s_client.allium` with a `Client` contract covering list and patch on pods. OVERVIEW §8 also needs list on Deployments and ReplicaSets, and ticket 22 settled the write mode whose patch preconditions §9.10 asked about in [ownership.allium](../../../docs/specs/ownership.allium): one JSON Patch per write with `test` preconditions, a 422 as a precondition failure and at most one Event per yield. The S1 probe loop in `src/knarr/s1_probe.gleam` is scaffolding that proved the path; the reconciler ([31](31-spec-then-build-reconcile-core.md)) is its real caller.

**What to build:** The full `k8s_client` module, specification first: the remaining operations and their Role verbs, pagination of a LIST, the error vocabulary callers branch on (RBAC refusal, conflict, not found, transport; a 404 and a 409 from the patch are reported as values and are not precondition failures), and the patch content type and preconditions 22 settled. Then the code, keeping the sans-IO shape 14 established, and the removal of `s1_probe` once 31 has a caller for the client, with the `NoPodEffects` clause and the Deployment's `ERL_FLAGS` updated in the same change.

**Non-goals:** Watch (OVERVIEW §8 defers it). Rate limiting (§9.8, ticket 24, built by [46](46-spec-then-build-poll-schedule-and-patcher.md)). Event reasons and the metrics (ticket 30).

**Blocked by:** 14, 22

**From 19:** config's `Discovery` needs two LISTs beside the pod LIST, both in knarr's namespace: Deployments selected on the label `knarr.io/enabled=true`, and ReplicaSets unselected. `list` on `deployments` and `replicasets` in `apps` is all config needs, and `Verbs` names the complete set with no `get`; OVERVIEW §8 was amended to match. Each listed Deployment carries name and uid so the invalid-key Event can name it. Each listed Deployment carries its name, uid, labels and annotations (null when the response has no map), each ReplicaSet its name, uid and the uid of its controller owner reference, and each pod the uid of its controller owner reference, which config matches by uid, never by name.

**From 24:** budget's `BackOff` and `PauseScope` read the response status and the Retry-After header, in seconds, of a failed patch and a failed list; this ticket shapes the values that carry them, and [46](46-spec-then-build-poll-schedule-and-patcher.md) consumes them.

**From 30:** [observability.allium](../../../docs/specs/observability.allium) names four Events, each of type Warning with reporting component `knarr` and one create attempt, never retried (`Events` `Conventions`): `AnnotationYielded` (ownership's Event), `PatchRejected` and `CleanupRejected` on a Pod by name and uid, and `ContractAbsent` on a Deployment by name and uid, so the Deployment LIST returns each Deployment's uid (k8s_client `Verbs` says so). Whether the create goes through core v1 or `events.k8s.io` is this ticket's. Every attempt counts on `knarr_events_total{reason, result}` as `created` or `failed` (`Catalogue` `Install`). The results on `knarr_lists_total{resource, result}` and `knarr_patches_total` come from the status the client surfaces, null for a transport failure, through `Catalogue` `list_result` and `patch_result`, so a 422 stays distinguishable from a 400 or 403 and a 429 from every other status (`Patches`, `Budget`). No line logs the token, the Authorization header, an apiserver response body, a whole Pod object or a raw URL with its query string (`Logs` `NeverLogged`).

**MVP critical path:** yes. Every read and write the reconciler makes goes through this module.

**Status:** done, except the probe removal, which waits for a caller and is [31](31-spec-then-build-reconcile-core.md)'s. See [the hand-back notes](#hand-back-notes).

## Hand-back notes

### What changed

- `docs/specs/k8s_client.allium`: the full `Client` contract. Values `Label`, `Owner` (the controller ownerReference), `Pod` with `pod_ip`, `ready` and `owner`, `ReplicaSet`, `Deployment` (raw labels and annotations), `InvolvedObject` (a pod or a deployment, by name and uid), `Event`, `Response` and `Failure`. Signatures `list_pods`, `list_replica_sets`, `list_deployments`, `patch_pod(…, document)`, `create_event`, the pure classifier `failure(response, operation)`, which matches the code's, and the predicate `precondition_failed`, which gives `Failure` the parameter position the pinned checker needs (a bare return is flagged as unused). Invariants: `Verbs` rewritten to the complete set with no GET, `Failures`, `RetryAfter`, `Pagination`, `ServiceAddress` and `EventCreate` added, `VerifiedTls`, `TokenReload` and `NoPatchWhileTerminating` kept. The §9.10 open question is gone. `budget.allium`: the header's expected-load line, `ListCadence` and `PauseScope` speak of the cycle's three LISTs. `knarr.allium` is unchanged: the probe still writes only its annotation, through the contract.
- `src/knarr/k8s_client.gleam`: pure builders for the three paginated LISTs (`limit=500`, the continue token encoded with `uri.query_to_string`, because `request.set_query` leaves `+` bare, and `labelSelector=knarr.io/enabled=true` on every page of the Deployment LIST, config's `Discovery`), the JSON Patch and the Event create; `base_request` brackets an IPv6 host. Pure decoders for each, a shared `failure(response:, operation:)` and `precondition_failed`. `ClientError` is `SendFailed`, `Refused(Failure)` or `UndecodableBody`; `Failure` carries `Reason`, the status and the Retry-After in seconds; the body is not kept (observability `NeverLogged`). `Event` names its `InvolvedObject`, `PodObject` or `DeploymentObject`, and the create picks `v1` `Pod` or `apps/v1` `Deployment` from it. The joins keep `send` injected; the LIST joins run the page loop. `patch_annotation` and the merge patch are gone. The reason for a status outside the named ones is `Other`, matching the spec's `other`, where the plan said `Unexpected`.
- `src/knarr/k8s_http_ffi.erl`: a request whose host is an IPv6 literal goes through an httpc profile of its own, `knarr_inet6`, with `ipfamily` `inet6`, started under inets' supervisor on first use. The default profile resolves with `inet` only and a bare `inet6` in `socket_opts` does not change that; the poller's later `{socket_opts, [{ipfamily, inet6}]}` is noted in Decision 0013 and not used. An IPv4 host is untouched.
- `src/knarr/s1_probe.gleam`: `should_patch` became the pure `probe_patch(pods:, pod_name:, value:) -> Option(String)`, which returns the JSON Patch document (the `deletionTimestamp` null test, then an add of the key, or a null test of the map and an add of the map when the pod has none); `patch` calls `patch_pod`; `describe` renders a `Failure` by status, reason and Retry-After, never the body. The log event names are unchanged, so `s1_logs.py` still reads them.
- `deploy/base/resources.json`: the Role grants `list` and `patch` on pods, `create` on events, and `list` on `apps` deployments and replicasets. The checker test and its render fixture follow.
- `.github/workflows/s1-proof.yml`: also runs on a pull request carrying the `cluster-s1` label, when it is added and on each push while it stays. Adding any other label does not run it. The plan put the gate in `ci.yml`; pull request #25 had already moved the job, so the gate went where the job is.
- Docs: [Decision 0013](../../../docs/decisions/0013-in-cluster-client.md) amended inline (Verbs, NoPatchWhileTerminating, the probe, new bullets for failures, pagination and IPv6, the IPv6 loopback and kind JSON Patch rows under Findings, the label gate, the gate figures, the reopen rows); OVERVIEW §8's client-boundary and RBAC bullets; the local cluster guide's Role sentence; evidence 14's README names the label.

### Notes for later tickets

- **The Events and AGENTS.md.** Each Event is knarr's own record, a new core Event object, not a change to a Pod or a Deployment. The Controller invariant's "writes only the annotations it owns, on live Pod objects" governs what knarr changes on Pods, so it stands unchanged.
- **31.** A pod maps to its Deployment through controller owners: `Pod.owner` names a ReplicaSet, and `ReplicaSet.owner` names the Deployment. `list_deployments` returns only opted-in Deployments; `opted_in` is still config's rule, and the match is by uid (config `Discovery`). The discovery cycle is three LISTs. A failure on any page fails that LIST. Remove the probe as 31's new box lists.
- **43.** `Pod.pod_ip` (`status.podIP`, `None` before one is assigned) and `Pod.ready` (the Ready condition is "True") are read; worker_contract's `Discovery` polls every pod with a pod IP whatever `ready` says.
- **46.** `Failure.status` and `Failure.retry_after` (whole seconds, `None` for an HTTP-date or no header) are what budget's `pause` reads; `Throttled` is the 429. The cycle is three LISTs.
- **32.** `patch_pod` takes `document`'s string as given and sends it as `application/json-patch+json`; `precondition_failed` is the 422 a failed `test` returns. A 404 or 409 is `NotFound` or `Conflict`, not a precondition failure.
- **30.** `create_event` takes the reason and message as given and the object as `PodObject` or `DeploymentObject`; the reason strings and messages are observability's and ownership's. The create is core v1, one attempt, and counting it on `knarr_events_total` is the caller's. `Failure` has no body to log; `SendFailed` carries no status, the null `list_result` and `patch_result` read.
