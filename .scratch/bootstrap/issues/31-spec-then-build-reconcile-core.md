**From 23:** [lifecycle.allium](../../../docs/specs/lifecycle.allium) is settled. This ticket's discovery process builds lifecycle's `View` for every pod the unselected pod LIST shows, from the three LISTs of one cycle: `target` from config's target set, `enabled` from the Deployment's settings (pod-deletion-cost always, safe-to-evict when `Settings.safe_to_evict` is true, empty for a non-target), `terminating` from `deletionTimestamp`, `deployment` from the name the pod's ReplicaSet's controller owner reference carries (k8s_client `Owner.name`, the empty string when the chain names no Deployment), and `held` from ownership `read` and `standing`; it hands them to lifecycle `Cleanup` `due` at each cycle in which every LIST succeeded, and the Removals become pending changes with purpose `cleanup` (`Scope`, `Pure`). config's `leaving` is retired: what left the target set is derived from each cycle's state. Each Removal carries the `deployment` of the View that made it, which it keeps while pending or in flight, and `done` takes the outstanding Removals so built (`Done`). On a pod that is not a target `knarr_annotations` counts only annotations standing owned, so a yielded or conflict record an opt-out leaves counts nowhere (observability `Standing`). The neutral write's null record for a disabled annotation falls to cleanup (reconcile `Neutral`). The "startup repair" the patch box below names is no pass of its own: a restarted knarr reconciles marked pods through the normal loop (lifecycle `Restart` `NoStartupStep`).

### Assumptions, stated here rather than asked

- Discovery is `-knarr discovery true`; the gate and `just image-check` run without it and are ready at tree start.
- The first tick runs at once on start, so readiness latches within the first cycle rather than after one LIST interval.
- A poll worker that does not answer within twice the poll timeout plus a second gives its pod a `timed_out` reading for that cycle rather than crashing the reconciler; `poller_http.send` returns within the timeout, so only a crashed worker, which is linked, takes that path. A reply that arrives after the wait is discarded by the actor with its "discarding unexpected message" warning: noise, not a wrong reading. Until ticket 46 a hanging worker can hold one slot of `poll_concurrency` past its batch; `poller_http_ffi.erl`'s deadline makes that unreachable in production.

### Corrections after review

The implementation was reviewed before the commit by three read-only audits (spec alignment, invariants and adapters, documentation and CI). Each defect below was fixed test first, in the `gleam-change` order.

- `fan_out` dropped a worker that missed the wait and the caller zipped the readings by position, so a hanging poll shifted every later pod's reading onto the wrong pod. Each item now comes back with its own result and a missing one is that pod's `timed_out` reading (`a_hanging_poll_is_timed_out_for_its_pod_alone_test`).
- A 422 on a yield kept nothing for the next LIST (reconcile `Rejected422`). `yields` now threads the memory and stores the refused operations as `write` does. No test can tell the kept operations from forgotten ones until ticket 32 gives `rejected`'s verdict a signal; `a_refused_yield_raises_no_event_and_is_rebuilt_from_the_next_list_test` covers the observable part.
